# Releasing

A checklist for publishing this package. It exists because the interesting parts of the
verification depend on software that cannot be redistributed, so the tree has to be checked
rather than trusted.

## 1. What must never be in the published tree

`.gitignore` already excludes these; check with `git status --ignored` before you commit, and
make sure none of them came back in a later `git add -A`:

| Path | Why |
| --- | --- |
| `demo-project/`, `*-project/` | An RPG Maker project ships copyrighted tilesets, BGM and SE. |
| `samples/` | Rendered maps are composites of that same art; the logs carry local paths. |
| `src/codebook/commands.json` | Generated from your installation; it embeds function bodies from a proprietary runtime. Users generate it with `npm run extract:commands`. |
| `src/codebook/autotiles.json` | Generated by `scripts/extract-autotile.mjs` from a specific installation's maps. Nothing reads it — the renderer evaluates the engine's own `Tilemap` tables at runtime — so it is engine-derived investigation output, and shipping it would contradict "no engine tables are vendored". |
| `src/bridge/FINDINGS.local.md` | The raw editor-investigation log: machine paths and internals of a proprietary binary. The publishable conclusions are in `src/bridge/FINDINGS.md`. |
| `.rpgmaker-mcp/` | Write backups, headless browser profiles, and the optional hand-made `live.env` with its token. |
| `dist/`, `node_modules/`, `*.tsbuildinfo` | Built artifacts. |

The one image that *is* published is `assets/lighthouse-night.png`, the lamp game's ending
picture: generated for this repository, 79 kB, and shipped because a build that reaches
outside the package for its own content is not a build anyone else can reproduce. Every
other file under a project's `img/` belongs to that project and stays out.

A quick sweep for anything that slipped through:

```bash
grep -rIn --exclude-dir=node_modules --exclude-dir=.git -e "$USERNAME" -e RMMZ_LIVE_TOKEN . | grep -v "README\|ACCEPTANCE\|CHANGELOG\|\.env\|src/"
```

The token string itself should appear nowhere — `RMMZ_LIVE_TOKEN` as an environment *variable
name* is fine and expected, a token value is not. `src/index.ts` reads it from the environment and
`plugin/RMMZLiveBridge.js` takes it from a plugin parameter. Say the name out loud rather than
relying on `$USER`: in Git Bash on Windows `$USER` is often unset, and `grep -e ""` then matches
every line in the tree, which looks like a clean sweep and is the opposite.

## 2. The identity fields

`package.json` carries `author`, `repository`, `homepage` and `bugs` for the account that
publishes this — change them if that changes. `LICENSE` is MIT with a generic
"rpgmaker-mcp contributors" line; replace it if you want your name on it.

## 3. Verify from a clean clone

A fresh clone proves the portability claims: it has no `.rpgmaker-mcp/live.env`, no
`src/codebook/commands.json` and no sibling `demo-project`, so if anything still depends on
them the run says so loudly.

```bash
git clone <your-url> && cd rpgmaker-mcp && npm ci
npm run build
node scripts/extract-commands.mjs "<MZ install>/data/corescript"

export RMMZ_PROJECT="/path/to/a/project/you/may/paint"
export RMMZ_CORESCRIPT_ROOT="<MZ install>/data/corescript"
export RMMZ_LIVE_TOKEN="<some token>"     # and put the same value in the plugin's Token parameter

npm run verify:full     # ~15 minutes; needs a Chromium-family browser
npm run smoke:chain     # the registered-command chain, writes undone
```

From the **tarball** rather than a clone, use `npm install` (npm strips
`package-lock.json` from a pack, so `npm ci` refuses there — a reviewer found that in the
runbook's first line) and leave out `npm run build`: the package has no `src/` to compile,
`tsc` prints its help and exits 1, and `verify:full` now says so and skips that entry
instead of failing the chain. That is the difference between "14 of 14" and what a stranger
can actually reproduce.

The last entry of `verify:full` is `verify:package`: it runs `npm pack`, unpacks the result into
`.rpgmaker-mcp/package-check/`, and checks *that* tree — allow-list both ways, no machine paths
or token in any shipped file, then the unpacked server spawned on its own and its registry
diffed against the working tree. The tarball it verified is left there for you to open, so the
thing you publish is the thing that passed.

`ACCEPTANCE.md` says what each suite settles and the numbers the recorded run printed, so you
can compare instead of re-deriving. Note that the authoring suites deliberately write into
`RMMZ_PROJECT` — point it at a project you do not mind painting.

## 4. Continuous integration

There is no workflow file here, because a hosted runner cannot do the two things this package
is judged on: it has no RPG Maker MZ installation to read engine tables and sample previews
from, and a licensed project to author into. The honest options:

- a self-hosted runner that owns an installation and a project, running `npm run verify:full`;
- or a public job limited to `npm ci && npm run build && npm run e2e` against a project you
  can commit — which excludes the renderer suites, the live bridge and both playthroughs, and
  should be labelled as exactly that.

## 5. Tag, then publish

```bash
npm version patch          # 0.4.2 is the release; the version is already in package.json,
                           # so this step is what also makes the git tag
git tag -a v0.4.2 -m "round three: suites that boot a game repair the template's missing key themselves, no suite crashes outside the acceptance game, and the high-level census is now one command (npm run census) — 65 tools, 15 suites"
git push --follow-tags
npm publish --dry-run      # read the file list: dist, plugin, scripts, assets, LICENSE, the docs
npm publish
```

Before the tag, one `npm run verify:full` end to end with its output kept — that run, not a
read-through, is what `ACCEPTANCE.md` quotes. It is 15 entries now (tsc, `e2e`, `roundtrip`,
`fidelity:sweep`, `e2e:live`, `verify:input`, `verify:newdata`, `session:e2e`, both builders,
both playthroughs, `census` — the acceptance game rebuilt from the shipped template, with its
census gated at zero writes — `smoke:chain`, and `verify:package`, which packs and then checks
the tarball itself) and it wants ports 3789–3800 to itself, so run it with no
other suite in flight: a second server on a port its predecessor still holds refuses to bind
and every call after it repeats the refusal.

The `files` field in `package.json` is the allow-list; `--dry-run` printing anything under
`samples/`, `src/codebook/` or a project folder means step 1 was not finished. Note that
`npm pack` does **not** consult `.gitignore` — it only follows `files` — which is why `src/`
is deliberately absent from that list: adding it would ship the generated
`src/codebook/commands.json` (proprietary engine bodies) and any local investigation notes
sitting beside it. Consumers get `dist/`; builders clone the repository.
